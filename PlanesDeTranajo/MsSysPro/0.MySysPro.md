# Mi idea para el mejor SysPro

## Pasos a seguir antes de empezar a trabajar
1. lee el archivo project_status.md
2. lee el archivo project_log.md
3. lee el archivo project_architecture.md
4. lee el archivo project_endpoints.md
5. lee el archivo project_functions.md
6. lee el archivo project_tests.md

## Pasos a seguir despues de terminar de trabajar
1. actualiza el archivo project_status.md
2. actualiza el archivo project_log.md
3. actualiza el archivo project_architecture.md
4. actualiza el archivo project_endpoints.md
5. actualiza el archivo project_functions.md
6. actualiza el archivo project_tests.md

## Pasos a seguir durante el trabajo (no estan ordenados aun)
- cera una lista de pasos a seguir dependiendo de la tarea que pidio el cliente.
- si `project_architecture.md` no existe, crealo. en cambio busca en el donde buscar el problema, o los cambios que se deben hacer.
- puede mirar `project_status.md`, `project_endpoints.md`, `project_functions.md`, `project_tests.md` para encontrar el problema, o los cambios que se deben hacer.
- si `project_log.md` no existe, crealo. en cambio busca si se intento arreglar el problema, o hay alguna restriccion que se debe seguir en cada paso que tiene que hacer.
- actualiza la lista de pasos con lo que encontro en los archivos que reviso.
- crea un plan de trabajo y un TODO list para cada paso que tiene que hacer. estos archivos deben estar en la carpeta `SysPro/PlanesDeTranajo/{yyyy-mm-dd_hh-mm-ss.{name_of_task}.md}`.
- conecta los pasos a seguir con los archivos que se deben modificar. por ejemplo, si el paso es "cambiar el color de fondo de la pagina", conecta el paso a seguir con el archivo `home.css`.
- intenta compilar el proyecto para verificar que no hay errores. si hay errores, corrige los errores y vuelve a compilar el proyecto.
- ejecuta el proyecto (si es seguro) para verificar que no hay errores. si hay errores, corrige los errores y vuelve a ejecutar el proyecto.
- si todo esta bien, actualiza los archivos `project_status.md`, `project_log.md`, `project_architecture.md`, `project_endpoints.md`, `project_functions.md`, `project_tests.md`.
- si hay algo que no esta bien, vuelve al paso 1 y repite el proceso.
- si todo esta bien, informa al cliente que el trabajo esta terminado.
- realiza tres deep thinking de cada paso a seguir (y saca una conclusion final) para asegurarte de que todo esta bien.
- genera el codigo que tiene que cambiar/agregar/eliminar. y lo cambia en un entorno virtual. y se lo para a un agente de IA para que lo revise con las condiciones que estan el los archivos markdown que tiene `project_xxxx.md`.
- si el agente de IA encuentra errores, corrige los errores y vuelve a generar el codigo.
- si el agente de IA no encuentra errores, informa al agente principal que el trabajo esta listo para ser desplegado.
- despues de que el agente principal de el ok, despliega el codigo en el archivo que se tiene que modificar.
- siempre tiene que tener las copias anteriores de los archivos que se van a modificar. por si acaso hay algun error.
- intentar siempre crear funciones muy pequeñas y modulares, que tengan una sola responsabilidad, que no dependas mas que de sus parametros, de las variables globales del sistema y variables de entorno (.env).
- cuando una funcion crece mucho, intenta dividirla en funciones mas pequeñas y modulares.
- cuando una funcion tiene muchas responsabilidades, intenta dividirla en funciones mas pequeñas y modulares.
- cuando una funcion tiene muchas dependencias, intenta dividirla en funciones mas pequeñas y modulares.
- cuando una funcion tiene muchas lineas de codigo, intenta dividirla en funciones mas pequeñas y modulares.
- los componentes en React, deben estar en archivos separados, y deben tener una sola responsabilidad.
- los botones, inputs, select, etc, deben estar en archivos separados, y deben tener una sola responsabilidad.
- las conexiones api al backend, deben estar en un archivo separado y documentado. con ejemplos de uso.
- para encontrar un error en el codigo, puede leer una funcion/clase/componente y saltar a la funcion/clase/componente que llama, y asi sucesivamente hasta encontrar el error. tambien puede buscar quien la utiliza para ver si hay algun error en la llamada.
